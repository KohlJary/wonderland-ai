## Review 016: Feature 002: Backend Note+Tag CRUD with Frontend Editor/Preview Integration

**GUID:** 01KRXV38QZVMMKXYET82Z5H4DN
**Files reviewed:** src/backend/api/notes.py, src/backend/models.py, frontend/src/App.tsx, frontend/src/EditorLayout.tsx, frontend/src/Editor.tsx, frontend/src/TagInput.tsx, frontend/src/Preview.tsx, frontend/src/api.ts, src/backend/main.py
**Verdict:** accept

### Approvals

- Cross-ticket coherence verified: contract-note-01KRXRTT and contract-note-004 specify POST /api/notes envelope — request {title: str, body?: str, tag_names?: str[]}, response {id: int, title: str, body: str, tag_names: str[], tag_ids: int[], created_at ISO8601, updated_at ISO8601}. Backend notes.py implements this exactly. NoteCreate enforces the request schema. NoteResponse serializes the response schema. create_note() returns 201. Frontend api.ts wraps createNote() identically. Editor.tsx calls it with correct payload. TagInput.tsx feeds tag_names into state. No contract drift.
- App entry point is wired correctly: App.tsx imports EditorLayout (not old placeholder), renders it as root. EditorLayout composes Editor (left) and Preview (right) side-by-side with proper state threading — onBodyChange callback threads body from Editor to Preview. Users see the full split-pane layout and preview updates in real-time as they type. Feature is rendered and integrated.
- Backend schema is sound: Note.body is Text NOT NULL with default='', correctly implementing the contract requirement that body is optional in requests but always stored as non-NULL string. note_tags association table uses CASCADE delete on note_id (correct — removing a note deletes its associations) but NOT on tag_id (correct — tags are shared across notes, removing one association doesn't delete the tag). The cascade semantics prevent orphaned tags and are documented.
- All seven CRUD endpoints per ticket-006 acceptance criteria are implemented: POST /api/notes (create, returns 201 with full note), GET /api/notes (list in reverse chronological order), GET /api/notes/{id} (read one, returns 404 if missing), PUT /api/notes/{id} (update atomically, returns 404 if missing), DELETE /api/notes/{id} (remove, returns 404 if missing), POST /api/notes/{id}/tags (associate tag by name, auto-creates if missing, idempotent), DELETE /api/notes/{id}/tags/{tag_id} (remove association, validates both targets, returns 404 if missing). Endpoints return proper status codes and response shapes. Acceptance criteria met.
- Tag association is atomic and handles edge cases: _associate_tags() deduplicates tag_names before creating associations, preventing UNIQUE constraint violations if same tag name appears twice in input. Uses db.flush() to ensure tag IDs are assigned before association. POST /api/notes/{id}/tags idempotently appends tag (no-op if already associated). DELETE validates both note and tag existence before removing. Implementation is resilient to repeated or out-of-order calls.
- Timestamp handling is rigorous: Note.to_dict() calls ensure_tz_aware() on every timestamp, converting naive datetimes to UTC and formatting as ISO8601 with Z suffix. All responses have consistent timezone-aware timestamps. Frontend receives ISO8601 Z timestamps and can parse reliably. No naive timestamps or +00:00 format leaking.
- Frontend keystroke buffer is correctly implemented: Editor.tsx writes {title, body, tags} to localStorage on every keystroke in handleTitleChange, handleBodyChange, handleTagsChange callbacks. On mount, useEffect restores from localStorage if present, hydrating component state. After successful save (createNote returns 200), clears localStorage. If localStorage JSON parsing fails, gracefully removes key and starts fresh. Buffer survives page reload.
- Preview pane is XSS-safe and handles graceful degradation: Preview.tsx uses DOMPurify.sanitize() to prevent XSS from script tags or event handlers embedded in markdown. Uses marked for parsing. useMemo hook avoids unnecessary re-parsing on every render. Catches markdown parse errors and displays inline error message rather than crashing. Empty body renders as empty (no error state needed). Production-ready.
- TagInput component correctly implements contract and handles UX edges: TagInput.tsx accepts {tags: string[], onTagsChange} props. Users type into input, press Enter or click Add, tag is added after trimming and deduplication (empty strings and duplicates rejected). Remove button removes tags via onTagsChange callback. Parent Editor threads this into state and localStorage. Tag flow from input through save to backend is cohesive.
- Error handling is surface-appropriate and actionable: Pydantic Field constraints (min_length, max_length, required) reject invalid input before endpoint code runs, automatic 400 response. HTTP status codes correct (201 on create, 200 on read/update, 204 on delete, 404 on missing). Frontend api.ts wrapper catches non-2xx responses, extracts error text, surfaces user-facing error message in Editor UI. Errors don't crash; they inform user and preserve state for retry.
