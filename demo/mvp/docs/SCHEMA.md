# Note Schema Contract

**Version:** 1.0.0  
**Status:** Stable  
**Last Updated:** 2026-05-18  
**Maintainers:** Backend (Tweedledum), Frontend (Tweedledee)

## Overview

This document defines the canonical schema for Note objects in the mvp-demo2 system. It is the single source of truth for the Note data shape, used by:

- Backend: SQLite schema definition, endpoint validation, persistence
- Frontend: Request/response validation, component state shape, storage contracts

Changes to this schema require joint negotiation between backend and frontend (Pair Protocol §IV). Breaking changes must be versioned and coordinated.

## Note Schema

```typescript
// TypeScript representation for frontend clarity
interface Note {
  // Primary Key
  id: number;
  
  // Content
  title: string;           // Required, non-empty, max 255 chars
  body: string;            // Optional, defaults to "", max 16384 chars
  
  // Tags (denormalized v1, normalization deferred to v2)
  tags: string[];          // Array of tag strings, defaults to []
  
  // Timestamps (server-generated, ISO8601 format)
  created_at: string;      // ISO8601 timestamp, immutable
  updated_at: string;      // ISO8601 timestamp, updated on each write
}
```

### Field Details

| Field | Type | Constraints | Notes |
|-------|------|-----------|-------|
| `id` | Integer | Primary Key, autoincrement | Unique identifier, generated by database |
| `title` | String(255) | NOT NULL, non-empty | User-visible note title |
| `body` | Text | Nullable, defaults "" | Markdown or plain text body |
| `tags` | JSON Array | Defaults to [] | Denormalized tag strings (v1 only) |
| `created_at` | DateTime(UTC) | NOT NULL, immutable | Set on insert via `func.now()` |
| `updated_at` | DateTime(UTC) | NOT NULL, auto-update | Set on insert, updated on every write |

### Invariants

These properties must **always hold** and are enforced at the database level:

1. **Primary Key Uniqueness:** Every note has exactly one `id`, and no two notes share an `id`.
2. **Title Presence:** Every note has a `title`, and `title` is never empty (>= 1 char, <= 255 chars).
3. **Timestamp Validity:** Every note has both `created_at` and `updated_at`, both in valid ISO8601 format, and `created_at` <= `updated_at` (created cannot be after last update).
4. **Immutable Creation:** Once set, `created_at` never changes. A note's creation timestamp is permanent.
5. **Tags Structure:** `tags` is always a JSON array of strings (or empty array), never null.

### Schema Evolution

**v1 (current):**
- Tags stored denormalized as JSON array in `notes.tags` column
- No foreign-key constraint to a separate tags table
- Tag creation is implicit on note insert (client supplies tag strings; server accepts them as-is)

**v2 (planned, deferred):**
- Normalize tags into a separate `tags` table
- Create `note_tags` junction table with foreign keys
- Add tag creation and lookup endpoints

**Migration Path:** v1 → v2 will require a backfill migration that:
- Creates the `tags` and `note_tags` tables
- Extracts unique tags from existing notes' JSON arrays
- Populates `note_tags` with the extracted associations
- Drops the `notes.tags` JSON column

This is documented so future implementations can plan the migration in advance.

## SQL Schema (SQLite)

```sql
CREATE TABLE notes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  body TEXT DEFAULT '',
  tags JSON NOT NULL DEFAULT '[]',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Indexes for common queries
-- (search and list operations will benefit from these in v2)
```

## Endpoint Contracts

These endpoints form the contract between frontend and backend for note persistence. See contract-note-01KRXRTT for the full OpenAPI definition.

### POST /api/notes — Create Note

**Request:**
```json
{
  "title": "My Experiment",
  "body": "Optional markdown content",
  "tag_ids": ["research", "experiment"]
}
```

**Response (201 Created):**
```json
{
  "id": 1,
  "title": "My Experiment",
  "body": "Optional markdown content",
  "tags": ["research", "experiment"],
  "created_at": "2026-05-18T14:55:29.467263+00:00",
  "updated_at": "2026-05-18T14:55:29.467263+00:00"
}
```

### GET /api/notes/{id} — Read Note

**Response (200 OK):**
```json
{
  "id": 1,
  "title": "My Experiment",
  "body": "Optional markdown content",
  "tags": ["research", "experiment"],
  "created_at": "2026-05-18T14:55:29.467263+00:00",
  "updated_at": "2026-05-18T14:55:29.467263+00:00"
}
```

**Response (404 Not Found):**
```json
{
  "detail": "Note not found"
}
```

### GET /api/notes — List Notes (v2 fast-follow, contract reserved)

**Query Parameters:**
- `skip: int` — pagination offset (default 0)
- `limit: int` — page size (default 20, max 100)

**Response (200 OK):**
```json
{
  "total": 42,
  "items": [
    {
      "id": 42,
      "title": "Most Recent",
      "body": "...",
      "tags": [...],
      "created_at": "...",
      "updated_at": "..."
    }
  ]
}
```

Results are sorted by `updated_at DESC` (most-recently-updated first).

## Validation Rules (Enforced by Backend)

All these are validated in `NoteCreate` (Pydantic model) and at the endpoint handler level:

| Validation | Rule | Rejection |
|-----------|------|-----------|
| Title Presence | `len(title) >= 1` | 422 Unprocessable Entity |
| Title Length | `len(title) <= 255` | 422 Unprocessable Entity |
| Body Length | `len(body) <= 16384` | 422 Unprocessable Entity |
| Tags Type | `tag_ids` is array of strings | 422 Unprocessable Entity |
| Timestamp Format | All timestamps must be valid ISO8601 | 500 Internal Server Error (bug if this fails) |

## Backward Compatibility

**v1 Stability:** The current schema (v1) is stable for the feature set it supports. Breaking changes will be versioned:

- Schema changes that add optional columns or change JSON structure without breaking existing code → patch version bump (v1.x)
- Schema changes that remove columns or add NOT NULL constraints → minor version bump (v1.x → v2.0)
- Contract shape changes (request/response envelope) → explicit contract negotiation (Pair Protocol §IV)

**Clients must be prepared for:**
- `tags` being an empty array (not null)
- `body` being an empty string (not null)
- Timestamps in ISO8601 format with timezone info

## Frontend Usage

**React State Shape:**
```typescript
interface NoteState {
  id: number;
  title: string;
  body: string;
  tags: string[];
  created_at: string;  // ISO8601
  updated_at: string;  // ISO8601
  isDirty?: boolean;   // Local state, not persisted
}
```

**localStorage Buffering:**
The frontend maintains a keystroke buffer in localStorage (under key `note-${id}-draft`). This buffer has the same shape as NoteState, allowing a save to merge the buffer into the backend.

**Validation on Client:**
The frontend validates the same constraints as the backend before submitting:
- Title non-empty (user feedback: "Note requires a title")
- Title max 255 chars (hard limit in input)
- Body max 16384 chars (guidance in UI; server enforces)
