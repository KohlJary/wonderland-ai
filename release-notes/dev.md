# Dev — unreleased

Active changes accumulating toward the next cut. On release, copy this file to `release-notes/<version>.md` and wipe back to header-only.

- **Milestone planning sizes by scope, not a fixed count.** The milestone-plan directive used to tell the planner to "target 3-7 milestones," which biased it toward over-bundling — on a content-heavy app it would cram auth + several entity types + media + draft/publish into one fat foundation milestone to hit the number, then the design phase's composition meeting would over-produce stories and starve on budget before shipping features. The directive now anchors on granularity (each milestone is one coherent, independently-shippable slice; split a fat foundation into auth / entity-substrate / relational-entity slices) and lets the count follow the work, with a soft ~3-12 sanity range instead of a hard target.

- **Design composition stops starving its commit phase.** The tdd-design composition meeting (features-from-stories) deadlocked repeatedly — its discussion phase ran all 3 rotations of 3-agent concern/nudge ping-pong and burned the whole meeting budget before the commit phase (where Rabbit actually ships features) got a turn, producing 0 features even on a lean milestone. The pre-existing "end discussion early when a feature ships" guard never fired because features are a commit-phase output. Capped the discussion phase to 2 rotations and bumped the meeting budget (0.40 → 0.60) so commit reliably gets turns. Makes every design pass more reliable, not just the one that surfaced it.

- **Milestone done_whens must be observable outcomes, not design tasks.** A milestone's done_when conditions are now explicitly required to be checkable outcomes ("admin can create a wrestler and it persists"), never design decisions ("name the architectural seams", "decide the match-composition model"). Baking a design task into a milestone's completion conditions made the tdd-design composition agents try to *resolve that architecture during feature composition* — spiraling into deliberation and shipping zero features. Architectural seams worth flagging belong in a `concern`, not a done_when.

- **Tests and import-probes now run under the project's own venv.** `run_tests` and `verify_imports` invoked the *substrate's* interpreter (`sys.executable`) instead of the project's `.venv/bin/python`. The substrate's environment doesn't have the project's runtime deps (fastapi, sqlalchemy, bcrypt, …) and pins different versions of shared ones (pydantic 2.12 vs the project's 2.13), so every test run died at collection with ModuleNotFoundError or pydantic version-skew errors — the recurring "can't actually run the tests" failure the Tweedles kept reporting. Both tools now resolve the project venv first (`_project_python()`, falling back to `sys.executable` when there's no venv). Consequence worth noting: tests were effectively *never running* before this, which silently masked real project-code defects (e.g. a generated module using pydantic `Field` without importing it). With tests actually executing, the M8 review loop can finally see those failures.

- **Feature composition no longer accumulates duplicate features across rotations.** Rabbit composes features by re-emitting his full feature list each rotation (refining slugs as he goes) — exactly like the milestone plan — but composition had no snapshot, so every rotation's features piled up as near-duplicates (wwu: 5 + 6 emissions → 11 features for ~6 surfaces, and decomposition only ticketed the canonical set, leaving the stale half as "features with no tickets"). Ported the milestone primary-speaker snapshot to features (`_apply_feature_snapshot` + `primary_speaker: white_rabbit` on the composition meeting): folds to the primary author's most-recent emission, dropping earlier rotations' stale slugs. Scoped to composition (primary-speaker meetings) so it never touches per-feature design meetings that edit incrementally.
